# AGENTS.md

## Cursor Cloud specific instructions

SAK Media Server (`sakms`) is a single self-contained Go server (module
`github.com/labbersanon/sakms`, entry point `cmd/sakms`) with a SolidJS + Vite
frontend under `frontend/`. SQLite is embedded (pure-Go `modernc.org/sqlite`,
auto-migrated on boot) and the BitTorrent/Usenet download engine runs
in-process, so no external database or download-client service is required to
run or test the app. All external integrations (TMDB, Prowlarr, Jellyfin,
Stash, StashDB/FansDB/TPDB, Trakt, AI providers, NNTP) are optional and
configured at runtime via the Settings UI. Standard commands/versions are in
`README.md`, `frontend/README.md`, `Makefile`, and `frontend/package.json` —
the notes below are only the non-obvious caveats.

- **The frontend must be built before the backend will compile.** `cmd/sakms`
  does `//go:embed static` from `internal/web/static/`, which is gitignored and
  generated by `pnpm build`. A bare `go build ./cmd/sakms` (or `go run`) fails
  with `pattern static: no matching files found` until `pnpm -C frontend build`
  has populated that directory. The startup update script already runs it once;
  re-run `pnpm -C frontend build` yourself after changing any frontend source
  (there is no watcher wired into the Go binary).

- **pnpm is pinned to 9.15.9 via corepack**, but the VM's global `pnpm` is a
  newer major. Run `corepack enable` (the update script does this) so the
  pinned version is used; otherwise version-sensitive commands may misbehave.

- **Scope Go build/vet/test to the server, not the whole module.**
  `go build ./...`, `go vet ./...`, and `go test ./...` fail on
  `cmd/sakms-node-tray` (a Fyne desktop system-tray app) because it needs
  OpenGL/Wayland system headers that aren't installed and aren't relevant to
  the media server. Use `./cmd/sakms/... ./internal/...` instead, e.g.
  `go vet ./cmd/sakms/... ./internal/...` and
  `go test ./cmd/sakms/... ./internal/...`.

- **CGO is on by default and go-nvml prints deprecation warnings** during
  `go build ./cmd/sakms`. These `nvml.h ... is deprecated` warnings are
  harmless — the build succeeds (exit 0). `make build` uses `CGO_ENABLED=0`;
  the default `go build`/`go run` uses CGO (a C compiler is present).

- **Running the server:** `go run ./cmd/sakms` needs no env vars or config —
  it listens on `:8080` and creates `./data/{sakms.db,secret.key,downloads/}`
  on first boot. On the very first boot it logs an `X-Api-Key` value exactly
  once (`API key generated ...`); capture it from the logs if a script needs
  header auth. First run in the UI creates an operator login, then set the
  Movies/Series library root folders under Settings → Library.

- **Workflows that identify media (Rename, Dedup) require TMDB configured** in
  Settings; without it a Scan returns cleanly with a "tmdb isn't configured"
  notice rather than erroring. `ffmpeg`/`ffprobe` (already on PATH) are only
  needed for Dedup/perceptual-hash/VMAF.

- **Frontend live-dev loop:** `pnpm -C frontend dev` serves the UI with HMR and
  proxies `/api` + `/healthz` to the backend on `:8080` (override target with
  `SAKMS_DEV_BACKEND`). Run `go run ./cmd/sakms` alongside it.

- **Tests:** frontend `pnpm -C frontend test` (Vitest); backend
  `go test ./cmd/sakms/... ./internal/...`. Regenerate the Go→TS DTOs with
  `make dto` (`go run ./cmd/gendto`) if you change `internal/apidto`.
